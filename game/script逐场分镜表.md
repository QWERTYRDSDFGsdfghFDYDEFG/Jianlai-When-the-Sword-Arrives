# script.rpy 逐场分镜表

## 使用规则

- 静止显示、硬切和 `dissolve` 使用的图片默认按 `1920 x 1080` 横版出图。只有已明确采用 ATL 裁切移动或缩放的图片才提高源图尺寸，不能先按 1920 出图、接入时再临时决定推拉摇移。
- 本表按 `script.rpy` 里每一次 `scene bg` 切换建立“执行镜头”；同一剧情场可以包含多个执行镜头。规划但尚未写入并测试通过的切点统一标记为“冻结资产”，不得进入人物精修出图队列。
- `背景` 优先按“主图 + 派生图”组织，而不是每场都完全重画。
- `立绘` 先写成建议占位，后续可以按真实素材名替换，但不能再把所有场次都理解成“普通站姿立绘”。
- `表情` 先写大类，不提前细拆到过多差分。
- `景别` 以 `远景 / 中景 / 近景 / 特写` 为主，默认通过独立构图或母图派生图完成；不得默认依靠运行时裁切和缩放改变景别。
- 每个执行镜头必须能回答：从哪句台词切入、使用什么资源、画面如何进入和退出、停留多久、声音如何衔接。
- 逐场动作和摆位统一遵守本表的“隐性控制口径”与项目统一风格，不再在每一场重复整套风格词。

### 固定字段说明

- `镜号`：按脚本中的画面切换顺序编号；同一剧情场有多张画面时继续细分。
- `脚本定位`：使用 `文件 + label + 行号范围 + 触发台词`，不能只写容易漂移的单独行号。
- `统一图名`：只写资源主体名，如 `c1_07_pq_run_v1`；Ren'Py 调用时再写成 `scene bg c1_07_pq_run_v1`。
- `制作方式`：固定使用 `背景＋独立立绘 / 双人整图 / 多人整图 / 事件CG / 母图派生 / 同图裁切 / 纯演出复用`。长对话默认使用“背景＋独立立绘”，整图只用于短时关键定格。
- `动作级别`：直接标明画面需要执行的动作强度与关系，如 `A2 关系动作` 或 `A3 事件动作`。
- `动作设计`：写清身体重心、手部、脚步、视线和入画方向。
- `粗略画面`：先用方框、圆点、箭头和明暗块确定机位、人物占位、动作方向、前中后景与对白留白；它是可修改的施工草图，不是最终美术稿。
- `动作参考`：固定记录“原文动作依据 + 相似图片参考 + 本场修改说明”，参考图只借姿势、重心、受力或镜头关系，不直接照搬人物身份、服装与场景。
- `镜头处理`：只写观众实际看到的画面变化；不得单独使用“推近、拉远、横移、跟随”等电影术语而不说明实现。
- `ATL 实现方式`：每镜必填。固定使用 `无 ATL`；转场写明 `with dissolve` 或硬切；需要静态图运动时，必须写出 Transform/ATL 的起止参数、时长、缓动、源图尺寸和安全延展区。
- `入出场`：分别写画面如何进入、如何交给下一镜。
- `停留节奏`：`D0 立即出现 / D1 短停顿0.3–0.8秒 / D2 情绪停顿1–2秒 / D3 随对白等待点击 / D4 连续演出段`。
- `声音`：记录配音、BGM、环境音和关键音效；脚本未接入的声音必须标明“待接入”。
- `连续性`：记录与前后镜必须一致的方向、服装、道具、光线和人物位置。
- `禁区`：明确这张图最容易被错误画成什么。
- `制作状态`：只使用下列可核验状态：
  - `已接入（正式图）`：脚本有调用、`bg_images.rpy` 有映射、磁盘文件存在，并且尺寸与本表规格一致。
  - `待替换（已有占位图）`：脚本已经能显示图片，但当前文件尺寸、画面内容或审核状态尚未达到正式标准。
  - `扁平占位图／母图源文件缺失`：运行时PNG存在，但缺少合格分层PSD，不能执行承诺的图层移动、显隐和派生。
  - `待替换（已有占位图）/Rough未审核`：P0已有运行图，但缺少合格的Rough审核记录；不得直接进入精修或正式图状态。
  - `资源缺失（脚本已调用）`：脚本和映射已经引用，但磁盘文件不存在；这是运行风险，不得写“已接入”。
  - `待出图`：尚无可用图片，脚本也未调用。
  - `规划未接入`：只完成分镜规划，尚无正式脚本切点。
  - `冻结（等待脚本确认）`：规划存在，但 `.rpy` 中尚未写入并测试通过对应切点；美术不得制作人物精修动作图，只能复用或补充无人物母图、空间结构草图。
  - `草图 / 待审核 / 已定稿未接入`：按真实制作阶段填写，不得与“已接入”混写。

### “整图”与“背景＋独立立绘”的选择规则

- `双人整图 / 多人整图 / 事件CG` 只适合短时关键定格：登场、动作结果、情绪高潮或少量台词。人物被画进整图后，程序不能单独切换其表情、视线、口型或显隐。
- 连续对话超过约 `12句`、跨越多个情绪拍点，或同一画面需要某个角色单独变化表情时，必须使用 `空背景＋独立立绘`。不能为了省资源把长对话钉死在一张多人整图上。
- 背景文件只画环境和不可交互物，不烘焙需要表情变化的主要人物。角色分别使用 `show`、`hide` 和表情属性切换。
- 独立立绘至少拆分为：基础身体/服装姿态，以及少量真正被脚本触发的表情状态。表情差分数量必须在 `.rpy` 触发点冻结后确定，不能先凭感觉画五六套。
- 整图可以作为长对话开始或结束时的短暂建立镜头，但进入连续对白后必须切到可交互的背景＋立绘层。

### 母图交付标准（强制分层源文件）

- “母图”不是一张可观看的PNG，而是后续能够真正移动、隐藏、替换和重新导出的分层源文件。只有同时交付 `PSD源文件＋预览PNG＋运行时导出PNG`，才允许在本表标记为 `母图可派生`。
- 母图源文件统一保存到 `art_source/chapter1/`，不由 Ren'Py 直接读取；运行时PNG仍导出到 `images/chapter1/`。序章湖区母图目标名为 `art_source/chapter1/c1_02_lake_master_v1.psd`。
- `c1_02` 湖区母图画布至少为 `2520×1080`，以覆盖 `c1_07` 横移所需宽度；普通1920×1080场次从母图安全区域导出，不把已经裁成1920的PNG反称为母图。
- PSD至少必须包含以下四个顶层组，组名保持稳定：
  1. `[01_远景山_天空]`：天空、云雾、远山分层；远山不得与天空永久合并。
  2. `[02_湖面_倒影]`：湖面底色、水纹、远山倒影、人物/特效倒影分别可控；倒影不能直接烘焙进湖面底色。
  3. `[03_中景高台_路径]`：湖岸、路径、高台、栏杆或结构物按可遮挡关系拆层，保证能改变人物入场路线与高台显隐。
  4. `[04_前景特效_人物占位]`：前景草石/遮挡、金色光圈与其他特效、人物剪影占位分别设为子组。人物占位只用于构图校验，默认隐藏，不得与背景合并。
- 可复用的金色光圈、水花、雾气、前景遮挡必须保留透明像素或蒙版；禁止破坏性擦除后再合层。调整层、蒙版、智能对象应尽量保留，不能只留下“背景副本＋最终合并层”。
- 正式人物不画进湖区环境母图。`c1_03` 的李槐和白鹿、`c1_06` 的于禄和谢谢、`c1_07/08` 的裴钱以及 `c1_09` 的对话立绘，都必须保留为独立角色资产或独立派生文件。
- 每次派生必须从PSD另存新文件或按图层组合导出，并在派生记录中注明：源PSD版本、启用/隐藏的图层组、裁切范围、新增人物/特效以及导出尺寸。
- 只有扁平PNG时，状态必须写为 `扁平占位图／母图源文件缺失`，不得宣称“从母图派生”，也不得继续以它为基础安排需要移动独立元素的正式资产。

#### 母图验收清单

1. PSD能够正常打开，画布尺寸、色彩空间和图层没有丢失。
2. 单独隐藏四个顶层组时，画面变化符合组名，不存在关键元素藏在错误组中。
3. 隐藏人物占位后能得到干净空场景；隐藏金色光圈后湖面能够自然补全。
4. 湖面、倒影、高台、路径和前景遮挡可以独立修改，不暴露合层后的破洞。
5. 能从同一PSD实际导出至少一张1920×1080静态构图和一张2520×1080宽幅构图，才算验证“可派生”。

### Ren'Py 镜头实现与源图尺寸规则

- 原则上优先使用 `静态画面 + 硬切/dissolve + 独立派生图`。ATL 只用于确实能增加叙事价值、且已在出图前锁定参数的少量镜头。
- `无 ATL`：源图 `1920 x 1080`，按屏幕一比一显示，不缩放、不移动；硬切不是 ATL，`with dissolve` 也只是转场。
- `横向裁切移动`：推荐源图至少 `2520 x 1080`，左右各留 `300px` 安全延展区；ATL 必须写明例如 `xalign 0.0` 到 `xalign 0.5`、`linear 4.0`。延展区不能放脸、手、武器尖端、关键道具或文字。
- `轻微推近`：不得直接放大 `1920 x 1080` 成图。采用时源图至少 `3840 x 2160`，以 `zoom 0.5` 适配 1080p，再移动到约 `zoom 0.55`；同时写明 `xalign/yalign` 锚点和持续时间。若不愿生成 4K，则改为两张 1920 派生图硬切或 dissolve。
- `拉远/抬升`：默认用另一张构图更开的派生图切换，不在单张图上做数字拉远。只有源图已包含完整画外区域并写明起止裁切框时，才允许 ATL。
- `跟随`：静态整图无法真正跟随人物动作。要么做宽幅母图的单向裁切移动，要么拆成多个定格画面；本表不再把“跟随”作为独立实现方式。
- `震动`：只能使用短时、低幅度 Transform，并写明次数和位移；不能把它当作动作图不足的补救手段。
- ATL 参数未填写的镜头，一律按 `无 ATL、1920 x 1080 静态显示` 制作。任何参数变更都必须先回改本表，再调整图片规格和脚本。

### 序章统一风格与禁区

- 风格统一：`东方幻想`、`宋代审美`、`半写实`、`山水志怪`、`人间烟火`、`沉静克制`、`自然情绪光影`、`低饱和高级灰`、`真实材质结构`
- 序章统一禁区：`古偶剧照感`、`仙侠网游风`、`二次元萌系`、`情侣海报感`、`过度唯美滤镜`、`页游特效感`

## 出图前的隐性控制口径

这部分不是替代分镜表，而是给整份表补一层更上游的判断标准。后续每一场出图，都默认先过这三道检查。

### 1. 对 `[物体]` 刻画来说，“透视”的精细度有优先级

- 先画准 `空间骨架`：地面、高台、栏杆、门框、屋檐、桥、湖岸线这类决定空间成立的硬结构，透视必须最稳。
- 再画准 `叙事焦点物`：人物手边、脚下、身上正在使用或被强调的物件，例如竹刀竹剑、葫芦、琴笛、灯笼、法袍下摆、长剑、书箱。
- 最后处理 `远景陪衬物`：远山、树丛、水纹、远处屋脊、散落小物可以概括，不需要和前景关键物用同一级精描。
- 默认优先级：`人物接触物 > 人物附近关键物 > 空间骨架 > 远景装饰物`。
- 不要把所有东西画得一样认真。对 VN 背景来说，真正有用的不是“全都细”，而是“该准的准，该收的收”。
- 只要某个物体承担 `受力`、`方向`、`站位`、`动作起点` 的功能，它的透视优先级就自动上升。

### 2. 对 `[画面]` 构成来说，“块面切分”的安排先于小细节

- 每张图先切 `大块面`，再补 `中块面`，最后才进小装饰；不要一开始就堆碎元素。
- 至少先明确三个层级：`主块面`、`副块面`、`留白块面`。
- `主块面` 负责第一眼读图，比如人物群、高台、湖面主斜线、书院门口主建筑。
- `副块面` 负责托住关系和节奏，比如道路转折、栏杆、树影、岸线、远山。
- `留白块面` 负责呼吸、对白承接、情绪停顿，不能被“怕空”心理填满。
- 前景、中景、后景尽量靠 `明暗`、`虚实`、`冷暖`、`大小` 拉开，而不是只靠堆物件来制造层次。
- 戏多、人多、动作强的场次，更要先把画面切成清楚的大块，不然最后会只剩“热闹”，没有阅读顺序。
- 凡是要兼容 Ren'Py 立绘叠加和对白框的图，中央和两侧都要预留安全块面，避免人物一进场就把画面挤死。

### 3. 对 `[视觉]` 效果来说，“画风”的潜规则比表面风格词更重要

- 画风首先不是笔触花样，而是 `同一世界的空间逻辑 + 光线逻辑 + 材质逻辑 + 人物逻辑` 是否统一。
- 同一组图必须默认共用一套潜规则：镜头高度接近、空气湿度接近、夜色明度区间接近、材质反应接近。
- 《剑来》这套图的“好看”，不是靠仙气滤镜，而是靠 `半写实`、`宋韵审美`、`克制情绪`、`真实材质`、`低饱和高级灰` 一起成立。
- 宁可 `收一点、灰一点、静一点`，也不要 `甜一点、亮一点、艳一点、仙一点`。
- 人物不能偶像化，场景不能样板化，特效不能页游化；一旦出现这三种倾向，哪怕单张图精致，也算跑偏。
- 所谓“统一画风”，本质上是让观者相信这些图发生在同一个人间，而不是每一场都换一个审美系统。

### 4. 三者冲突时的执行优先级

- 优先保证 `空间可信`，其次保证 `块面清楚`，最后才是 `风格修饰`。
- 如果一张图风格很满，但空间站不住、块面读不清，就不能算合格。

## 生成图片前的准备工作

- 先把每个场次的 `统一图名` 与当前 `script.rpy` 中的 `scene bg` 做对应，确认是否可以用占位图继续推进脚本。
- 先根据本表判断每张图的性质：分层母图 / 派生图 / 独立成图 / 纯切分图。优先建立并验收 `c1_02_lake_master_v1.psd`；没有分层源文件时，`c1_02`、`c1_04_stage_*`、`c1_10_cpa_*` 只能称为构图基准或独立成图，不能称为可执行母图。
- 先给每张图补一份简短的 `透视主次 / 块面草图 / 风格禁区` 备注，哪怕只写三行，也比直接进细节可靠。
- 先明确“本场是否需要独立立绘”：若场次可靠整图推进，则暂用整图占位，避免提前拆差分；若需要对话立绘，则先补占位立绘入场代码。
- 先建立“统一图名 / 复用关系 / 资源状态”清单，减少以后反复重画同一构图的风险。
- 先把本表里的场次真正写入 `.rpy`，锁定切点、触发台词和玩家点击节奏，并完成一次从前镜到后镜的运行测试，再交给人物动作图制作；“已经规划成可以写”的状态不等于脚本冻结。

### 脚本冻结门（人物精修出图的强制前置条件）

一张带具体人物动作的分镜只有同时满足以下条件，才能从 `冻结（等待脚本确认）` 转为 `待出图`：

1. `.rpy` 中已经写入真实的 `scene/show/hide` 切点，不以文档里的设想代替代码。
2. 每个切点已经绑定明确的触发台词或旁白，动作冻结点已经确定，例如“滚开”显示时究竟处于抬手峰值、落手过程还是动作结束。
3. 玩家点击顺序、转场方式和停留节奏已经在游戏中从前一镜跑到后一镜，确认没有台词提前、画面滞后或连续性断裂。
4. 使用的图名、`bg_images.rpy` 映射方案、ATL需求和源图规格已经确定。
5. 测试通过后，在本表记录脚本文件、行号范围、触发台词和测试结果，才允许人物精修。

脚本冻结前，美术允许做的内容只有：

- 无人物环境母图，例如新建合格分层的 `c1_02_lake_master_v1.psd` 湖区空间；已有扁平PNG不在此列。`c1_04` 高台若要承担母图职能，也必须另交符合本节标准的分层PSD。
- 方框、剪影、箭头级粗略分镜，用于验证切点方案，但不得细化身份脸、服装褶皱、手势峰值和表情。
- 已有角色母版的查验与整理，不得因为母版存在就提前派生本场人物动作成图。

脚本冻结前禁止：人物精修动作图、最终群像、依赖某句台词瞬间的手势与表情、为了规划镜头而提前生成正式资产。若脚本切点后续改动，先退回 `冻结（等待脚本确认）`，重新审核粗略分镜。

### 单场画面的具体制作流程（先粗后细，可随时修改）

每一场都按下面顺序推进。没有完成前一阶段，不直接进入精细出图：

1. `读原文与脚本`：圈出本镜真正要定格的瞬间，记录出场人物、动作起点、动作结果、情绪和关键道具。
2. `画粗略场景`：先做一张低成本画面草图。背景只画地面、高台、门、湖岸等空间骨架；人物先用圆点或剪影占位；用箭头标动作与入画方向，并给对白框预留空间。
3. `找动作参考`：先以原文为准，再找一至三张相似图片。优先找相同的身体重心、手脚受力、人物距离和镜头角度；若没有完全相同的图，可以分别参考腿部、手势和构图，再组合修改。
4. `写参考修改说明`：明确哪些部分保留、哪些必须改。例如“只参考前脚制动和伸掌，不参考服装；把单人姿势改成李槐挡在三人之间；镜头改为横版中远景”。
5. `审粗图`：只检查剧情读不读得懂、站位是否跳轴、动作是否成立、重复人物是否有必要入镜、后续是否容易派生；此时允许移动、删除或缩小人物，不处理脸和衣纹。
6. `锁定母图与派生关系`：通过后再固定透视、光向、人物左右关系和道具数量。先按“母图交付标准”验收PSD及四大图层组，再允许建立派生关系；只有扁平PNG时必须改记为独立成图，不能假装复制母图修改。
7. `细化与接入`：最后才补身份脸、服装、材质、表情与光影；审核通过后再定稿并接入 Ren'Py。

建议每场至少留下三份过程记录：`rough_v1`（首次粗图）、`rough_v2`（修改后粗图）、`final_v1`（首张定稿）。粗图未通过时继续增加 `rough_v3`，不要覆盖上一版，方便回退。

### P0画面的 Rough 强制审核门

- 所有P0画面在精修、生成正式人物、细化服装或制作光效前，必须先提交 `Rough_v1`。赶工、已有占位图、已经写入脚本或“核心key art”都不能成为跳过理由。
- Rough只允许使用：黑白/灰度大块、人物剪影、空间结构线、动作箭头、视线箭头、地平线和安全区；禁止用漂亮脸、衣纹、材质与特效掩盖构图问题。
- 每张P0 Rough必须量化记录：`画布尺寸 / 地平线Y位置 / 机位角度 / 主体中心坐标 / 主体占画面高度 / 主动势起止点 / 主要留白区 / 对白框安全区`。
- 审核只回答五个问题：三秒内能否读懂剧情瞬间；人物是否站得住；动作方向是否唯一；留白是否服务下一拍；是否出现站桩海报或网游宣传图倾向。
- `Rough_v1未审核` 时，制作状态不得进入 `草图、待审核、已定稿`。审核不通过则出 `Rough_v2`；只有记录“Rough审核通过＋日期/确认人”后，才允许进入细化。
- P0已有运行时图片但没有Rough审核记录时，只能标为 `待替换（已有占位图）/Rough未审核`，不能倒推认定现图已经通过构图审核。

### 动作参考的判断顺序

- 第一依据永远是 `原文和脚本冻结点`：先确定这一刻正在发生什么，不能先看到一张漂亮姿势再反推剧情。
- 第二依据是 `相似图片`：可使用照片、影视截图、武术或舞台动作资料、已有分镜，只解决人体结构、受力、动势和构图问题。
- 第三步是 `按角色与场景改造`：换成项目角色的年龄、身高、性格、服装、道具与空间关系，并服从前后镜连续性。
- 找不到一张完整参考时，允许组合参考，但必须写清各图分别参考什么，避免拼成身体受力不统一的动作。
- 参考图不能替代身份标准；人物脸、服装和气质仍以项目角色标准为准。

### 连续镜中重复人物是否需要再次画出

- 判断标准不是“这个人上一镜出现过没有”，而是“这一镜是否还需要他来说明空间、关系、动作结果或对白对象”。
- `必须画出`：人物正在说话或行动；承受动作结果；决定前后遮挡或危险方向；缺少后会让观众误解站位或以为人物离场。
- `可以弱化`：人物仍在场但不是本镜重点，可只保留背影、肩部、边缘剪影、虚化前景或局部肢体，既交代连续性又不抢画面。
- `可以不画`：上一镜已经建立其位置，本镜景别收紧后人物自然处于画外，并且镜头内仍有锚点能解释其位置。分镜表要注明“仍在场，位于画外”，不能默认为消失。
- `重新画出的方式`：连续镜不从零设计重复人物，而是复制母图中的人物层，再按镜头目的调整裁切、表情和小动作；身份、服装、道具、左右方向不能漂移。
- 该规则适用于后续所有场次，尤其是群像拆成近景、反应镜和动作结果镜时。

## 制表依据

- Ren'Py 官方文档：图像通过 `scene / show / hide` 管理，画面变化通过 `with` 处理转场，因此本表把资源、入出场和转场拆开记录：<https://www.renpy.org/doc/html/displaying_images.html>
- Ren'Py 官方文档：音乐、音效和配音使用不同通道，因此“声音”字段必须明确音频类别：<https://www.renpy.org/doc/html/audio.html>
- Toon Boom Storyboard Pro 官方文档：一个场景可包含多个 Panel，Panel 默认记录对白、动作、时间提示和备注，因此本表采用“剧情场—执行镜头”两级结构：<https://docs.toonboom.com/help/storyboard-pro-24/storyboard/reference/views/panel-view.html>
- Toon Boom Storyboard Pro 官方文档：分镜需记录 Panel 的持续时间并按时间线检查节奏，因此本表增加 `D0–D4` 停留节奏：<https://docs.toonboom.com/help/storyboard-pro-25/storyboard/timing/about-timing.html>
- Unreal Engine 官方文档：复杂演出按 Shot 组织并允许不同 Take，因此规划资产与当前已接入镜头必须分开管理：<https://dev.epicgames.com/documentation/unreal-engine/sequences-shots-and-takes-in-unreal-engine>
