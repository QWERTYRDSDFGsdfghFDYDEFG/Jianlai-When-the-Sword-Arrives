## 参考如何转化

参考来源为[光荣特库摩繁中官网](https://www.gamecity.com.tw/sangokushi8-re/system.html)的[事件对话截图](https://www.gamecity.com.tw/sangokushi8-re/img/system/system_29_01.jpg)。截图中姓名在正文左侧独立成列，续行对齐正文；浅纸色阅读区连续稳定，不规则灰墨与纸纤维集中在场景衔接处。

本项目拟采用“头像旁姓名单独一行、下方正文”的排法。这是结合现有头像系统的适配建议，不把上下排法误记为原游戏的排法。姓名与正文的文字起点对齐，固定首行位置，让短句与长句切换时阅读位置稳定。

纸面以低饱和暖灰、米灰为试色方向，与堂内暖灯和门外冷夜共同检查。上沿及两侧柔化，正文后方保留稳定底色；不能把整块阅读区变透明，也不能用高亮白纸压过场景。头像下缘在UI中柔和收束，保留脸部与衣领清晰度，不把头像重新放回场景。

## 当前预检发现

| 项目 | 已确认的现状与证据 | 明天的处理 |
| --- | --- | --- |
| 对话区衔接生硬 | 现版是深色矩形底、左侧实色竖线和顶部横线；720p实机截图可见清楚的水平切口。`screens.rpy:123–138`、`dialogue_ui.rpy:6–21`。 | 制作专用纸墨底及边缘过渡，装饰限定在外围；正文区先保证对比度。 |
| 姓名与正文缺少稳定的版面关系 | 姓名字号32、正文33；姓名框额外内缩16，正文起点不同。文字组采用垂直居中，长句换行后有上移风险。`screens.rpy:181–212、265–305`。 | 姓名独立行、墨色略重，与正文共用文字左边界；首行固定，正文留够换行空间。 |
| 小屏字号配置没有传到这套对白样式 | `gui.rpy:410–411`设置small正文45、姓名54，但实际`say_label`与`say_dialogue`写死32、33；专用窗高也固定270。 | 试点样式显式适配small，并一起调整行距与容纳高度；不能仅改通用字体参数后就认为小屏已生效。 |
| 头像偏小且下缘像裁切素材 | 当前头像等比装入202×210的逻辑区域；在1280×720里整个区域约135×140，脸部更小。两人的裁切宽高比不同，裴钱实际占约202×210，朱敛约202×169；现有截图中胸像下缘可见较直切口。`dialogue_ui.rpy:115、121、126–129、212–224`。 | 先调显示裁切、面部尺度、眼线和下缘遮罩；两人各自校准，不拉伸原图，不先重画角色。浅纸底上重点检查残边、白边和衣领。 |
| 按钮小，且桌面与触屏功能不同 | 桌面按钮文字19逻辑像素，720p约13像素；触屏菜单仅四项，没有快存和快读。现有浅米色按钮文字依赖深色底，不能直接搬到浅纸上。`gui.rpy:180–184`、`screens.rpy:488–508、526–541、2003–2018`。 | 底部功能带与纸面一起排版，重定默认、悬停、选中、不可用状态的颜色；触屏同时检查点击面积和六项可达性。 |
| 只换皮肤不能解决前后演出缺口 | T133及T138以后仍是已知黑场。迎客图没有挽臂动作，直接接“她竟然挽着师父”，该动作现在由对白交代。`script_chapter2.rpy:376–413`。 | 完整播放迎客→三句头像对白→旁白，检查是否读得懂、切换是否突兀；不擅自恢复取消的CG或改写台词。如有必要，另列演出任务。 |

还有两项实施风险：

- `say`与`quick_menu`为全局共用入口。新方案应按08-05专用头像标记限定，避免其他章节、双人头像、吴懿心声和普通旁白一起换样式。离开T137、回退、读档时都要正确恢复。
- 项目使用1920×1080逻辑画布；窗口比例与素材比例不是同一件事。应按实际游戏内容区定位底栏，在窄屏、宽屏留边情况下检查，不能用拉伸背景或贴到系统窗口外沿来实现“适配”。旧P5适配验收不能转用为纸墨界面的通过依据。

## 明天的制作顺序

1. **固定基线与版面草稿。** 开工重新查看工作树和本计划，确认现有素材。使用真实雪茫堂背景与两张现有头像，先排姓名、正文、底部六按钮的安全区域。以裴钱短句和朱敛最长句同时验证，不只排短句。
2. **交付两张实景样张。** 一张裴钱、一张朱敛；统一纸色、纸墨边缘、头像尺度、文字起点和按钮位置。用1280×720实际阅读大小检查。先确认视觉方向再进行跨文件接入，避免再次把功能通过当成美术通过。
3. **接入08-05试点。** 沿用现有头像标记、角色定义与保存逻辑，新增独立纸墨样式；文字、姓名、按钮由引擎绘制，不烘焙进背景。静态材质与遮罩优先，不在首版加入墨迹扩散、呼吸或翻页动画。
4. **做适配与边界验收。** 检查实际内容区、长句换行、两个人物的脸部比例、底部点击区域，以及T134进入和T138退出。桌面与small/touch分别测试，修正后只重测受到影响的项目。
5. **定稿并登记。** 用户确认视觉后，将采用状态、适用范围和新验收写入08-05制作记录；更新分镜、图片/UI索引及必要的项目入口。新材质按项目命名规范保存；P5历史记录继续标明停用，不能被覆盖成新方案记录。

## 验收清单

- 两张视觉样张：裴钱“她竟然挽着师父。”与朱敛“你没见少爷都僵硬了吗？只不过碍于形势，不好直接推开罢了。”。第三句正常推进，角色不误切、姓名不串行。
- 先认人、再读姓名、再读正文；姓名和文字起点稳定，最长句完整，正文不进入按钮区，短句不会让整个文字组漂移。
- 头像无黑白方框、残边、扭曲或明显胸像截口；纸纹不穿过文字，边缘柔化后仍能看清雪茫堂的空间和灯光。
- 1920×1080逻辑画布、1280×720、960×540及非16:9窗口（1024×768、1600×700）检查。若系统限制窗口大小，记录实际尺寸；手机真机与模拟small/touch分开报告。
- 六按钮的点击、悬停、禁用与自动/快进状态可辨；点击菜单和快存快读不误触推进。鼠标、Enter、Space、Esc、回退、隐藏/恢复界面、回看返回均可用。
- 在T134、T135和T136各做一次隔离存读档；T138向前回退，再正向推进。读取可用的旧版测试存档时核对界面，原用户存档只允许隔离副本测试；缺少合适旧档时明确保留未验证项。
- 抽查普通对白、双人头像、吴懿心声及普通旁白未被试点样式影响；运行lint并核对图片路径、角色、label/jump。全十二章不是本次局部验收范围，不宣称已完成全章回归。
- 工作副本、测试存档、缓存、截图放在独立QA位置，保护现有用户改动与正式存档。视觉通过和功能通过分别记录。
