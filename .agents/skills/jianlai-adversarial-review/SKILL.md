# 剑来对抗式代码审查

在当前《剑来》仓库内执行可追溯的只读审查。完整流程及报告格式的唯一来源是 [审查流程](../../../game/Codex/adversarial_review.md)，执行前必须读取。相对路径以本技能目录为起点，仓库根目录是其上三级；不要依赖固定盘符。

1. 读取适用的项目 `AGENTS.md`、`README.md` 和与改动相关的验收依据，检查已有修改。按流程固定比较基线、目标文件及上下文版本，避免漏掉暂存内容和相关未跟踪源码。
2. 由协调者准备中性输入包，实际启动三个独立上下文的子代理，依次完成“发现 → 核证 → 裁决”。传入原始代码、需求及结构化证据，不继承开发者自评或全量聊天。三个角色按流程各自核查原始材料；子代理不能再次递归启动这套流程。
3. 争议最多补证一轮，按风险安排隔离验证。真实缺陷可以被双方共同认可；没有证据的反驳不能抹去问题，不能确定的条目保持待验证。
4. 交接及交付前复核版本，汇总确认、驳回、待验证及未执行检查。审查默认只读，不自动修改代码、提交或外发。如果子代理不可用，明确标记独立审查未执行，不能以角色扮演冒充完成。

用户可以说：“对当前未提交改动做对抗式审查。”也可以指定文件、基线、提交范围或待复核报告。范围没有改动时据实说明，不擅自扩大到全仓。

当作为指定角色被调用时，仅完成分配的角色任务并向协调者返回结构化结果；不要另起团队或读取测试标准答案。
