# 场景阶段检查与返工

本文件只维护此 Skill 的阶段门槛和退回方法。人物长期身份、风格与命名仍以项目对应标准为准，不在此复制整套美术规范。

## 检查证据

每项检查写出：检查对象、观察位置、看见了什么、与哪份依据比较、结论与未确定部分。引用具体文件及内容哈希；视觉检查指向实际查看的图，运行检查指向对应版本的截图或日志。判断成立也要说明观察，不能只写“通过”。

三类结论分开记录：

- **可机械核对**：路径与哈希、母版及实际请求字段的绑定、逐人检查是否齐全、阶段顺序、重试次数及授权证据。脚本不能证明请求记录真实、代理确实看过图或脸与母版相似。
- **视觉复核**：角色是否像母版、动作是否可信、关系是否读得出、构图是否有效；由实际看图的独立复核者给出可追溯意见。
- **用户采用**：是否作为最终图、母版或游戏资源，必须来自用户实际决定；一开始已明确授权的范围直接沿用。

禁止用单一平均分抵消硬错误。人数、身份、剧情时刻、解剖侧别、主客关系、必要路径、严重肢体错误或错误引用中的任一未解决问题，都不能靠画风高分通过。

## 八阶段门槛

检查 ID 对应制作记录。条件不适用时写明原因，不能把“没检查”记成“不适用”。

| 阶段 | 检查 ID | 必须观察的内容 | 典型成果与证据 |
| --- | --- | --- | --- |
| brief | source_scope、narrative_focus | 当前确认稿、准确时刻、在场/画外/回忆人物、情绪焦点、前后衔接；事实与补全分开 | 场景任务单及脚本/分镜来源快照 |
| references | identity_basis、reference_roles | 逐角色身份清单、脸部母版采用状态、脸是否可见、身份与服装参考分工、跨场尺度、允许变化及道具 | 逐人绑定母版和标准；实际打开图像 |
| composition | story_relation、framing、staging | 谁在迎谁、谁看谁、动作目的；镜头为叙事服务；不把回忆画成对峙；对白留白 | 镜头描述或布局示意 |
| space | layout、grounding、staging | 内外轴、入口和目的地、人物前后、同伴体量、足点与接触、共同光源；无明显穿插 | 平面/侧面示意；需要时的3D占位截图 |
| sketch | identity、staging、anatomy、continuity | 按下节逐人验脸；服装轮廓、手脚和重心、道具数量/侧别、前后镜头连续性、已选机位 | 线稿与各自母版、相邻定稿的独立复核 |
| color | identity、staging、structure_preserved、palette_light | 彩稿逐人重新对母版验脸；线稿人数、姿态、站位、视线、道具未漂；固有色、受光、虚实边缘及细节密度一致 | 彩稿与母版、通过线稿的独立复核 |
| preview | identity、staging、actual_composite、dialogue_safe_area | 实际显示图逐人验脸；叠放的alpha边缘、透体洞、彩边和位置；对白布局下头、手势、重点可见 | 实际预览及查看记录；注明非实机或实机 |
| delivery | identity、staging、provenance、adoption_scope | 最终交付图逐人身份与复核指纹一致；原生/目标尺寸、显示处理、采用与接入授权、索引及必要验证 | 最终图身份复核、文件指纹及交付记录；接入时附运行证据 |

无人物背景的 `identity_basis`、`identity`、`anatomy`、`staging` 可不适用，并记录无人物原因。有角色但全部脸因剧情背影或完整遮挡不可见时，仅 `identity` 可不适用，不能宣称脸部已验证。未显示足点且无器物接触时 `grounding` 可不适用，但仍检查尺度和前后关系。整张不分层CG可将 `actual_composite` 记为不适用，不能因此跳过对白检查。明确不用作游戏画面的素材才可免对白安全区检查。

在任务单中补上本图特有条件。例如：迎客者在堂内、来客从入口回应；挽臂固定为吴自身右手接陈自身左臂；回忆画面中刀尖朝地、四人共享空间。这些是对应场次条件，不是所有图片都要照搬的构图。

## 逐角色身份验收

- references 开始时列齐本图角色，逐人绑定已确认脸部母版和身份标准；存在角度辅助图时核对适用性，它不能替换母版。角色名单、母版与标准写入 `identity`，实际工具请求写入各次 `identity_input`，字段见 [记录格式](record-format.md)。
- sketch、color、preview、delivery 都逐人填写 `review.character_checks`。同看整图和脸部局部：在内存中放大原图，并对照母版及已有同角度参考；没有同角度参考时说明透视判断的不确定处，不能据此重设计五官。局部查看不要求保存新裁图，须记录原图指纹、位置、查看方式和实际查看事件。
- 分别观察脸型与下颌、可见五官的比例及位置、年龄感、发际线与发型轮廓。侧脸优先核对额鼻唇颏轮廓、下颌和耳位；服装、发髻、玉簪或“能认出角色”均不能替代五官核对。四项具体观察齐全才可判身份通过。
- 按成图实际分辨率判断能否辨认，不设未经验证的固定像素阈值，也不把 AI 放大补出的细节当作原图证据。小脸、糊脸或关键特征不足应记 `unverified`，不能用 `not_visible` 豁免。`not_visible` 只用于剧情本就要求的背影或完整遮挡，并说明视图及遮挡。
- 任何角色 `fail` 或 `unverified` 均阻断身份通过。脸不稳先回查母版、角度和实际输入，在用户许可的原位局部编辑能力内解决；不带着漂移继续上色，也不靠反复整图重生成碰运气。

## 站位与动作空间验收

- 有角色的 composition 开始前，把 `staging` 写入现有制作记录：机位/俯仰、稳定地标与地面分层、动作目标、动作或器物所需范围、通路、跨镜对应，以及逐人的位置、足点支撑、身体朝向、视线、景深尺度和遮挡。先按剧情确定目标与空地，再安排人物；不得因图中江、门或台阶位于某侧就自行改变动作目的。
- 对照已有前后镜，用同一地标解释人物、动作区域和去向；换机位可改变画面左右，不可默认为地理布局也改变。相邻镜已有图时实际打开并纳入计划证据；尚无成图时注明依据的确认分镜与未验范围，不伪称已完成跨镜视觉验证。无连续镜头或无移动时说明原因，不强造后续动作。
- 每个人分别核对六项：位置是否相对地标正确；足点或接触是否有支撑；头肩、躯干、骨盆和脚的朝向是否共同成立；视线是否指向本场指定对象；校正景深、姿态及地面高差后体量是否连续；遮挡是否合理且保留叙事所需轮廓。不同角色可有不同的视线任务，不能为了整齐强迫同向站立。足点画外等局部不适用必须说明，只检查实际可见部分。
- 全景另外核对手势/道具是否指向正确目标，物体后续展开或显形是否有可解释的空间，人与物是否占住必要通道，镜间位置变化是否有原因。仅写“脚在路面上”“几个人都看得见”或登记精确像素坐标，不足以通过。没有可靠尺寸和机位依据时不编造米数、透视精度或碰撞结论。
- 换背景或机位后，复用旧人物前先证明旧姿态的俯仰、朝向、足点和遮挡仍适用；不适用时先修调度，在授权和原位工具能力范围内调整人物。平移/等比缩放不能代替转身，直接镜像会连带改变人物自身左右、衣襟及道具侧别。3D和平面占位用于辅助，最终仍要看实际画面。
- space 先独立核对方案；sketch、color、preview、delivery 再对同一张实际画面逐人填写 `placement`，并检查全景的 `staging` 项。身份通过不能抵消位置失败；背影照样验位置。任何一人位置 fail/unverified，或动作空地、通路、跨镜关系未解决，都不能放行。查看标记、平面示意和局部放大可以只在内存中进行，不要求新增预览文件。
- 每次尝试与复核绑定 `staging_sha256`，记录格式见 [站位方案与版本绑定](record-format.md#站位方案与版本绑定)。方案改变后重新核对受影响阶段；不能只换摘要复制旧 pass。脚本验证计划、证据和检查项的对应关系，不识别画面中的真实站位，也不替代独立目检。

## 参考与成果的锁定

1. 读取来源时记录路径、用途、采用依据和哈希。临时生成图作为构图输入时，不能替换身份母版的职责。
2. 有角色的每次 image 尝试，所有脸部母版都必须在 `inputs`。生成式调用还须出现在真实请求的 `referenced_image_paths` 中，并登记调用标识、原始参数与精确提示词；写在 sources 或提示词里不算传图。非生成的局部编辑可登记原图像素保留及实际写入/脸区差分证据，但仍须带母版并复核本次成图。
3. 阶段通过后锁定成果指纹；下一阶段保留上阶段成果及原始母版的职责。生成式上色或修订可能重画脸，必须重新验身份，不能承诺逐像素保留。
4. 既有已确认线稿可直接作为本轮线稿成果复核，无需强制重画；前四阶段仍要从现有资料恢复并留下依据。
5. 来源或成果改变时，不覆盖历史哈希伪装验证仍有效；从依赖该变化的最早阶段重新验证，下游原有“通过”不可继续沿用。允许新建文件时可保留旧尝试并开续做记录；用户要求原位修改且禁止新文件时，不能强建快照或替换原件。现有证据不足以恢复可核验记录时保留阻断，说明缺口。
6. 全局任务依据变化影响所有下游；仅某阶段候选变化时，失效范围从该阶段开始。重新核对可复用的旧成果，记录理由，不机械重生成所有图。

## 返工决策

复核者每次输出一条可执行的问题说明：

```text
问题：右前方来客反而从堂内向外迎请，主客关系颠倒。
证据：待验线稿中的脚步和手势，与当前场次“吴懿迎客”冲突。
退回：composition；重新核对 space 后再进入 sketch。
只改：两人的内外深度、朝向和迎请动作。
保留：已确认的厅堂、角色身份、服装、共同灯位。
复查：新线稿主客关系；连带检查左右手、同伴位置和衣襟侧别。
```

| 缺陷 | 退回位置 |
| --- | --- |
| 角色/时刻/剧情归属错、资料冲突 | brief 或 references |
| 情绪表达错、把回忆画成对立、镜头关系不成立 | composition |
| 动作目标、展开范围、跨镜地理或主客调度错 | composition，重验 space 及后续；不先移动人物碰运气 |
| 通路不通、脚底浮空、尺度、朝向、视线或遮挡错 | space，并重验线稿；机位改变先回 composition |
| 换脸、年龄漂移、错侧道具、多手、动作僵硬 | references 核对后 sketch；局部可修则在 sketch 修 |
| 上色改了姿态/脸/衣装，光色不统一，碎纹过多 | color；若原线稿已有缺陷则退回 sketch |
| alpha彩边、透体洞、遮挡说话表情、摆放不当 | preview 或对应素材阶段 |
| 路径错误、注册缺项、实际游戏表现出错 | delivery / 接入验证，不重画已通过美术 |

默认每阶段初稿后最多两轮自动修订；独立复核本身不耗生成次数。退回早期阶段不重置该阶段已有次数。记录实际工具调用，包括未采用结果；不能通过改任务名、清空尝试、称作“新方案”绕过上限。工具故障也记录原因和已试方案，不进行无界重试。

达到上限或出现“修一处坏两处”、复核者分歧时，保存断点、最佳已有成果、缺陷和可选处理，再交用户决定。用户明确授权增加次数时记录新增授权和限额，不默认重新无限尝试。遇到无法补齐的关键身份、历史衣装或剧情冲突，只暂停依赖它的工作。

## 独立复核与降级

有角色的 space 需独立核对空间方案；sketch、color、preview、delivery 各有独立身份与站位复核。传入中性的需求、各角色原始母版和待验整图，不能传入“请确认已经没问题”或只给制作方裁剪过的局部。复核者必须按上节同时看整图与脸部局部；交付图与已独立复核的最终图指纹相同，可沿用该观察并明确出处，不强制再生成或另存预览。

无法实际看图、工具不可用或没有独立代理时，相关项保持未验证；不伪造通过，不用像素统计替代身份判断。可报告已有图的待修正或待复核状态，明确未满足的门槛；是否创建或保存候选服从用户本次范围。若用户另行授权跳过某项，保留该决定及验证缺口，不把未执行写成通过。

## 采用与接入

- 候选可以完成制作记录并交付，状态仍为“候选”；美术通过、用户确认、已复制到项目、已接入、实机通过分别记录。
- 未确认候选留在生成器/工作区；明确保留或采用后按项目规范复制。长期在项目里引用的正式资产必须存在于项目资源目录，不依赖个人生成目录。
- 接入须沿当前素材调用链验证；仅更新文档不需要启动游戏。实际改动图片定义/脚本后，检查相关 label/jump、角色定义、图片音频路径及 lint；实机至少覆盖本镜与前后边界、对白遮挡、存读档、回退/回看。记清检查版本、范围和未运行项目。
- 对动态素材的扩展任务，继续执行 `game/AGENTS.md` 的完整循环逐帧验收，不把本流程静态通过用于证明动画合格。
