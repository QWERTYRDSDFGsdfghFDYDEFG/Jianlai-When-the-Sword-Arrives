# 剑来场景制作

将一张场景图片做成可追溯、可续做的制作任务。先建立场景依据与检查条件，再调用图像工具；不能用一次生成加一段自评代替此流程。

用户指定原位修改、禁止整图重生成或新建文件时，优先遵守这些限制；本 Skill 的过程稿、快照和候选流程不构成例外。编辑既有图片前先确认工具支持所需的原位局部修改；无法确认就停止依赖该能力的操作，不生成新图再覆盖原件。

## 开始与续做

1. 读取适用的 `AGENTS.md`、`README.md`，检查工作树；沿项目规则读取本次需要的剧情和资源规范。安装目录为 `.agents/skills/jianlai-scene-production/`，向上三级为仓库根；不固定盘符。
2. 从用户已确认的剧情定位当前场次和前后镜头。第二章先读 `game/Codex/chapter2_storyboard.md` 的当前部分，再读实际脚本；旧 T 编号、旧工作簿与历史验收不能代替当前稿。整章尚未确认时先完成剧情阶段，不越过章节制作约定。
3. 查 `game/Codex/character_image_index.md`、涉及角色标准与 `game/image_catalog.json`，实际打开每个角色的脸部母版与适用角度参考。有角色时读取 `game/Codex/character_generation_workflow.md` 和具体角色规则，其他资产操作按需读 `asset_pipeline_sop.md`。身份以 `game/lh/` 已登记母版为准，场景图只能辅助连续性。
4. 检查是否已有本图制作记录；存在则续做，不重新初始化。旧 v1 仅供只读诊断，按记录格式补证后才可继续；不把版本号改成 v2 后沿用旧通过。允许创建新图及记录时用下方工具初始化，先填写任务范围、既有授权、剧情依据、不可变条件、允许变化项及尚未解决的问题。用户本轮要求与此前明确授权都有效，不反复索要相同许可。
5. 向用户给出简短步骤与验证点。项目要求 Plan 的任务，已有明确批准即可执行；只有缺失的决定会实质改变结果才提问，并继续其他独立准备工作。普通出图授权允许自动推进至最终候选，不自动表示确认采用、替换角色母版或接入游戏。

## 每张图一份记录

先读 [记录格式与工具用法](references/record-format.md)。记录模板位于 [scene-record.template.json](assets/scene-record.template.json)，通过脚本初始化，避免手工遗漏阶段。

从仓库根运行（`python` 代表当前环境已确认可用的 Python 3；不可用时使用已发现的运行时，不自行安装依赖）：

```text
python .agents/skills/jianlai-scene-production/scripts/scene_record.py init work/art/chapter2/c2_new_scene/record.json --scene c2_new_scene --request "制作已确认分镜中的场景图" --project .
python .agents/skills/jianlai-scene-production/scripts/scene_record.py check work/art/chapter2/c2_new_scene/record.json
python .agents/skills/jianlai-scene-production/scripts/scene_record.py status work/art/chapter2/c2_new_scene/record.json
python .agents/skills/jianlai-scene-production/scripts/scene_record.py fingerprint game/lh/cpa/cpa_face_standard_01.png
```

- `work/art/章节/场景任务/record.json` 保存长期制作记录；已有对应记录时保留历史，不重复初始化。只有用户范围允许新建文件时才建立或链接新记录。
- 单个记录对应一张可交付画面；纯背景、人物差分等拆成多个交付文件时，各自建记录，互相写明依赖，不将多张图共用一次视觉通过结论。
- 将用户要求的终点写入 `task.stop_after_stage`：只做出图前准备用 `space`，只看线稿用 `sketch`，完整候选用默认 `delivery`；初始化可用 `--stop-after space` 等参数。达到终点后交付本次成果，不自动继续上色或生图。用户后来明确要求继续时，保留已通过记录并更新请求、授权和终点。
- 逐角色母版、精确提示词、实际工具请求中的参考路径、输出路径和哈希、失败原因、各阶段逐人身份复核均进入 v2 记录；参考登记不能替代实际传图。过程图留在生成器或任务工作区；项目记录可指向这些原图，但未确认的过程图不复制进 `game/`。
- 每次工具返回后先保存结果及当前状态，再开始下一步。新聊天先执行 `check`、`status`，复核源文件和最后通过的成果；变更的剧本、母版或画面会使依赖它的结论失效，按 [检查与返工规则](references/quality-gates.md)处理。
- 脚本不生成图片、不替人评画、不自动批准阶段、不替换素材；退出成功仅表示记录结构与已记录证据符合机械检查。

## 阶段执行

读取 [检查与返工规则](references/quality-gates.md)，按顺序执行八个阶段。每阶段都要有成果、针对本场的观察、文件证据和结论；不能只打“好看/合格”分数。

1. **brief／场景任务单**：明确剧情时刻、画面用途、人物关系、情绪焦点和前后衔接，划分原文事实、用户确认与美术补全。
2. **references／参考包**：分别锁身份、衣装、道具、环境、风格与跨镜尺度；评估复用已有环境的可能。参考冲突显式记录，不让模型自行选择所谓最新标准。
3. **composition／镜头方案**：登记机位、地标、动作目标、动作所需空地、通路、跨镜关系和逐人站位方案；先安排动作发生在哪里，再安排人如何面对它。按 [站位与动作空间验收](references/quality-gates.md#站位与动作空间验收) 检查，不能直接平移旧人物替代新机位下的调度。通常先提出一个有依据的方案，仅有实质取舍时比较两案。
4. **space／空间验证**：有角色时由独立复核者对照站位方案，检查动作目标、占用范围、通路、人物前后、朝向、视线、尺度、遮挡及接触。可在内存中标记原图或查看简单平面示意；复杂场景按需要用3D占位。足点落地和3D无碰撞均不能证明调度或透视正确。
5. **sketch／简洁线稿**：首次调用图像生成之前，前四阶段必须完成并通过检查。先解决同一个人，再推进关系动作、重心和体量；脸不稳时回查母版与角度，优先在许可范围内解决头部局部，不带着错误脸继续上色。
6. **color／上色**：保留通过线稿的构图，每次生成实际输入全部角色脸部母版；彩图重新逐人对照母版，不能仅检查与线稿相似。按本场确认风格统一光色；近期纸本参考不自动覆盖用户的其他明确要求。
7. **preview／使用预览**：重新核对实际显示图中的逐人身份和对白框遮挡；分层资产必须真实叠放检查。生成的同框示意不算透明层合成证据。区分独立预览与游戏实机。
8. **delivery／交付**：核对最终交付图的指纹与逐人身份复核；同一指纹可复用独立复核观察，不必重画。交付成图、采用状态、简短检查结果和未解决项；依用户授权处理登记与接入。游戏接入必须另有实际运行证据，不能用候选美术通过代替。

从 composition 开始绑定同一份 `staging` 方案摘要。sketch、color、preview、delivery 每次复核同时逐人检查身份与位置；上色后重验，不能只沿用线稿结论。方案变更使旧摘要对应的通过失效，先重新核对依赖它的阶段。

每阶段开始前运行 `check`；通过一个阶段后再次运行并保存结果摘要。机械检查失败先修记录或证据问题，不继续出图。视觉检查失败按问题类型退回对应阶段。

## 工具与独立复核

- 进入位图生成/编辑阶段时，读取当前可用的 `imagegen` 技能并遵守当前图像工具说明，默认使用内置工具；不私自改用付费 API、写新的生图客户端或获取凭证。工具不可用时保存断点并说明原因。
- 代码绘制的平面、几何占位与文字排版用于设计验证，不冒充最终画作；现有可编辑 PSD 的图层和蒙版调整可使用适合的原生工具。实际生图、修图遵循当前工具与用户授权。
- 导演/协调者负责场景任务单与依赖；制作执行者负责生成和修订；另启独立上下文的复核者核看关键视觉阶段。使用 `collaboration` 子代理，不创建用户侧的新聊天。
- 有角色的 space，以及 sketch、color、preview、delivery 的身份与站位检查均需独立复核。向复核者传入原始需求、确认依据、逐角色母版、待验画面及检查项，不传入制作方“已经通过”的结论。复核者按 [逐角色身份验收](references/quality-gates.md#逐角色身份验收) 同看整图与脸部局部，逐人报告五官、脸型、年龄和发型的具体观察；衣装、发髻或角色可分不能代替脸部一致。
- 资料准备和独立检查可并行；有依赖的空间、线稿、上色和修订必须串行。不重复套用项目的对抗式代码审查技能。
- 没有独立复核工具时注明“独立复核未执行”，可完成不依赖它的工作；不得以角色扮演伪造独立通过，交付仍保留待核项。

## 收尾与范围

- 状态使用“当前使用／候选／待修正／停用”，另记用户是否确认以及是否接入；模型复核通过不能升级为用户已确认。
- 角色图生成、修改或确认后按根 `AGENTS.md` 更新身份索引，链接本图记录；仅用户确认的母版变更和可复用身份经验写入角色标准，不把新图反向变成母版。
- 定稿进入项目时复制已确认原图并核对哈希；默认目标1920×1080，记录工具原生尺寸与实际显示方法，不能虚报像素尺寸或默默拉伸。当前授权不足以改变尺寸时保留原图并说明差异。
- 获得接入授权后，核对引用再注册资源和稳定代号，运行 `tools/build_image_catalog.py --check`，按影响范围做 Ren'Py lint 和切镜、对白、存读档、回退/回看实机验证。未运行就写明，不沿用旧验收。
- 交付包含修改文件、采用资产、实现结果、验证结果、未验证项和风险。保留旧资产及制作记录，不批量删除、不自动推送或对外上传。
