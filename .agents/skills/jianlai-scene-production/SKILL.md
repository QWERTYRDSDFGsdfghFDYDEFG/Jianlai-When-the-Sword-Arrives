# 剑来场景制作

先确定交付物是整段分镜台本，还是其中一个镜头的正式素材，再建立对应的剧情依据、制作记录与检查条件。不能用一次生成加一段自评代替此流程。

用户指定原位修改、禁止整图重生成或新建文件时，优先遵守这些限制；本 Skill 的过程稿、快照和候选流程不构成例外。编辑既有图片前先确认工具支持所需的原位局部修改；无法确认就停止依赖该能力的操作，不生成新图再覆盖原件。

## 先确定交付物

- **分镜台本**：用户说“分镜稿”“画分镜”“手绘分镜”或“分镜头台本”，默认交付带镜号与旁注的多格粗草图，沿用用户提供的手绘台本形式。按下方“分镜台本流程”执行，交付终点是可读、可修改的镜头安排。
- **正式素材**：用户明确要求单镜正式线稿、背景、CG、立绘或上色，或要求按已确认分镜继续既有素材任务时，沿用相应授权，执行“正式素材记录”和“正式素材阶段”。不把此前明确授权的正式线稿改回粗台本。
- 只说“线稿”或“继续”时，先查最近明确的交付要求和当前任务阶段；仍存在会改变结果的歧义才询问。粗台本检查通过不等于获准进入精绘。普通分镜请求不自动升级为单镜素材制作。

## 开始与续做

1. 读取适用的 `AGENTS.md`、`README.md`，检查工作树；沿项目规则读取本次需要的剧情和资源规范。安装目录为 `.agents/skills/jianlai-scene-production/`，向上三级为仓库根；不固定盘符。
2. 从用户已确认的剧情定位当前场次和前后镜头。第二章先读 `game/Codex/chapter2_storyboard.md` 的当前部分，再读实际脚本；旧 T 编号、旧工作簿与历史验收不能代替当前稿。整章尚未确认时先完成剧情阶段，不越过章节制作约定。
3. 查 `game/Codex/character_image_index.md`、涉及角色标准与 `game/image_catalog.json`，实际打开每个角色的脸部母版与适用角度参考。有角色时读取 `game/Codex/character_generation_workflow.md` 和具体角色规则，其他资产操作按需读 `asset_pipeline_sop.md`。身份以 `game/lh/` 已登记母版为准，场景图只能辅助连续性。
4. 正式素材已有单图记录时，对最新一份运行一次 `status`，从最早受影响的阶段续做。剧本、母版、机位、站位及已通过成果的指纹仍适用时，引用已有依据和观察，只补本次差异。沿用的审核须能追到原版本。旧 v1 只作历史诊断，按记录格式补证。新图且允许建文件时才初始化记录。分镜台本沿用当前章节分镜文档中的制作依据与记录，见下方流程。
5. 向用户给出简短步骤与验证点。项目要求 Plan 的任务，已有明确批准即可执行；只有缺失的决定会实质改变结果才提问，并继续其他独立准备工作。正式素材出图授权允许自动推进至本次约定的终点；分镜台本停在粗台本交付。两者均不自动表示确认采用、替换角色母版或接入游戏。

## 分镜台本流程

本节用于镜头叙事设计；后文的单图记录与八阶段用于正式素材，不将粗台本记为正式素材的 sketch 通过。工具能力、原位修改限制和项目剧情确认要求仍适用。

1. **拆解段落**：依据已确认剧情和当前采用的镜头顺序，列出“镜号—画面动作—对白/旁白—声音—切换条件”。按动作、注意力和信息变化划分镜头，不机械地一句话一格；不恢复已停用或被用户删去的镜头。
2. **组织台本页**：默认纵向排列多行，每行左栏镜号、中栏横向画框、右栏对白与演出说明，另列时间或推进条件，接近用户参考。镜内默认游戏的 16:9 画幅；整页依可读性安排，不受正式单镜 1920×1080 尺寸约束。格数依剧情范围决定，不为凑满页增加剧情。只指定一镜时，仅画该镜必要的动作关键格，不补造其他镜头；同镜多关键格用子编号并标明“同一镜头”。
3. **画粗草图**：用简化人物、姿态线、剪影和建筑轮廓交代景别、机位、视线、动作目标与前后遮挡。保留角色体型、衣装和道具等辨识依据，必要时标姓名；脸部只画到足以读懂表情与朝向。省略密集排线、材质纹理和精细五官。先让读者看懂谁在哪里做什么；粗画不免除比例、站位和动作方向检查，也不代表角色脸部已通过正式素材验收。
4. **补齐演出信息**：需要时用箭头标人物运动和镜头运动，分清两种含义；旁栏写对应对白/旁白、声音、停顿及切换。视觉小说按实际演出注明“点击推进”“某句后换图”或自动演出的预计时长，不给全部镜头硬填秒数。无对白写“无对白”，未定时间写“待定”，不编造。交付页必须能对照画格读到说明；生成文字有误时仅用已确认支持且获准的原位编辑方式排字修正，无法做到则标明未完成项。不要在台本整体要求中加入“无文字、无箭头、无对白”。
5. **按顺序独立复核**：让复核者实际查看整页，对照原始需求与确认剧情，逐格复述事件，核对镜号、视线与运动方向、人物出入、空间连续性、切换与停顿，以及旁注是否对应且可读。发现叙事或构图问题时修改相关格，不靠增加细节补救。这里检查叙事可读性；正式素材的逐人脸部精度验收留到其制作阶段。
6. **记录并停在本次终点**：在已有章节分镜文档的对应部分记录所覆盖镜号、实际请求与参考、工具结果路径及哈希、具体检查结论和待定项，保留历史与采用状态；没有适用文档时，仅在允许新建记录的范围内建立。交付粗台本与简短说明。用户已确认选定镜头且明确授权正式素材制作后，才为该镜沿用或初始化单图记录，进入下方阶段；已有授权不重复询问。

## 正式素材记录

先读 [记录格式与工具用法](references/record-format.md)。记录模板位于 [scene-record.template.json](assets/scene-record.template.json)，通过脚本初始化，避免手工遗漏阶段。

从仓库根运行（`python` 代表当前环境已确认可用的 Python 3；不可用时使用已发现的运行时，不自行安装依赖）：

```text
python .agents/skills/jianlai-scene-production/scripts/scene_record.py init work/art/chapter2/c2_new_scene/record.json --scene c2_new_scene --request "制作已确认分镜中的场景图" --project .
python .agents/skills/jianlai-scene-production/scripts/scene_record.py status work/art/chapter2/c2_new_scene/record.json
python .agents/skills/jianlai-scene-production/scripts/scene_record.py fingerprint game/lh/cpa/cpa_face_standard_01.png
```

- `work/art/章节/场景任务/record.json` 保存长期制作记录；已有对应记录时保留历史，不重复初始化。只有用户范围允许新建文件时才建立或链接新记录。
- 单个记录对应一张可交付画面；纯背景、人物差分等拆成多个交付文件时，各自建记录，互相写明依赖，不将多张图共用一次视觉通过结论。
- 将用户要求的终点写入 `task.stop_after_stage`：只做出图前准备用 `space`，只看线稿用 `sketch`，完整候选用默认 `delivery`；初始化可用 `--stop-after space` 等参数。达到终点后交付本次成果，不自动继续上色或生图。用户后来明确要求继续时，保留已通过记录并更新请求、授权和终点。
- 逐角色母版、精确提示词、实际工具请求中的参考路径、输出路径和哈希、失败原因、各阶段逐人身份复核均进入 v2 记录；参考登记不能替代实际传图。过程图留在生成器或任务工作区；项目记录可指向这些原图，但未确认的过程图不复制进 `game/`。
- 生成或实际写回后，将真实请求、结果指纹、观察和当前状态写入单图记录。一次 `status` 同时检查证据和下一步，`check` 是同一校验的另一入口。无需为每次查询另存报告。剧本、母版或画面变动时，按[失效与返工规则](references/quality-gates.md)重查受影响的证据。
- 脚本不生成图片、不替人评画、不自动批准阶段、不替换素材；退出成功仅表示记录结构与已记录证据符合机械检查。

## 正式素材阶段

读取 [检查与返工规则](references/quality-gates.md)，按顺序执行八个阶段。每阶段都要有成果、针对本场的观察、文件证据和结论；不能只打“好看/合格”分数。

1. **brief／场景任务单**：明确剧情时刻、画面用途、人物关系、情绪焦点和前后衔接，划分原文事实、用户确认与美术补全。
2. **references／参考包**　分清对话框前的立绘和站在场景内的人物。前者按对话布局定裁切与表情，后者按镜头定全身角度、受光、承重脚和遮挡。每人锁定脸部母版、适用角度、衣装和有左右侧别的道具。按本镜最终显示大小预判可见五官。需要观者认脸却只能看见窄颊时，先解决镜位或角度；剧情要求的完整背影按背影视图核对。
3. **composition／镜头方案**　先把动作目标和所需空地放进已确认的底板，再排人物。以同一画幅和共同地标记录每人的地面层级、足点、相对身高、前后顺序，以及脚尖、胸胯与视线的方向。对照前后镜确定来路和去向。若靠哪侧站或朝哪边行动无法从资料确定，且会改动整组人，只澄清这一个决定再画。[站位与动作空间验收](references/quality-gates.md#站位与动作空间验收)
4. **space／空间验证**　简单站姿和已锁定机位可用二维剪影按实尺试摆。用户指定 3D，或二维无法判定多人前后遮挡、高低差、纵深动作或大型道具占地时，先搭可重投影的粗三维模型。用地面俯视查足点、器物投影和通路，用目标机位查支撑脚、主动作关节、视线和遮挡。复核者在实际显示比例下先描述“谁对什么做了什么”，再对照分镜。若方向或动作读错，在模型里改到读对才进线稿。记录发现的偏差、改动及对应视图；比例未知的净空保留待核。
5. **sketch／简洁线稿**　前四阶段通过后，按已验机位和姿态画线稿。用过 3D 时，将通过的机位图实际用于绘制，生成式调用预先核对可提交的参考数量，确认机位图和必需的角色脸部母版均能实际传入。超出工具能力时先解决参考输入，再发起生成。

   先把返回的立绘或分件以预定足点和大小叠进原背景，再决定是否精绘。逐人对照母版检查脸、年龄、头身、衣装与道具，核对支撑脚、肩胯、手的侧别及“肩—肘—腕—目标”能否读清。透明素材另看发丝、袖口、鞋边与人物之间的遮挡。底板与已验方案吻合、仅某个人物画错时，保留验过的分件，返工该人的姿态线稿。若整组关系、机位或动作空地有误，先退回构图、重验空间。旧姿态须同时满足本镜机位、承重和侧别才可复用。按最终合成尺寸再验一次，通过才上色。
6. **color／上色**：保留通过线稿的构图，每次生成实际输入全部角色脸部母版；彩图重新逐人对照母版，不能仅检查与线稿相似。按本场确认风格统一光色；近期纸本参考不自动覆盖用户的其他明确要求。
7. **preview／使用预览**：重新核对实际显示图中的逐人身份和对白框遮挡；分层资产必须真实叠放检查。生成的同框示意不算透明层合成证据。区分独立预览与游戏实机。
8. **delivery／交付**：核对最终交付图的指纹与逐人身份复核；同一指纹可复用独立复核观察，不必重画。交付成图、采用状态、简短检查结果和未解决项；依用户授权处理登记与接入。游戏接入必须另有实际运行证据，不能用候选美术通过代替。

从 composition 开始绑定同一份 `staging` 方案摘要。sketch、color、preview、delivery 每次复核同时逐人检查身份与位置；上色后重验，不能只沿用线稿结论。方案变更使旧摘要对应的通过失效，先重新核对依赖它的阶段。

每次阶段交界运行一次 `status`。刚登记上一阶段结果的校验，可同时作为下一阶段的开工检查。跨会话、写回或输入变动后重新校验。身份和站位可由同一位独立复核者在同一张图上一次检查、分别记录；画面或对白叠层有变化时，重新查看实际结果。机械校验报错先修记录，视觉复核未通过就退回相应阶段。

## 工具与独立复核

- 进入位图生成/编辑阶段时，读取当前可用的 `imagegen` 技能并遵守当前图像工具说明，默认使用内置工具；不私自改用付费 API、写新的生图客户端或获取凭证。工具不可用时保存断点并说明原因。
- 代码绘制的平面、几何占位与文字排版用于设计验证，不冒充最终画作；现有可编辑 PSD 的图层和蒙版调整可使用适合的原生工具。实际生图、修图遵循当前工具与用户授权。
- 导演/协调者负责场景任务单与依赖；制作执行者负责生成和修订；另启独立上下文的复核者核看关键视觉阶段。使用 `collaboration` 子代理，不创建用户侧的新聊天。
- 分镜台本按其流程进行整页独立复核；正式素材有角色的 space，以及 sketch、color、preview、delivery 的身份与站位检查均需独立复核。向复核者传入原始需求、确认依据、逐角色母版、待验画面及检查项，不传入制作方“已经通过”的结论。正式素材的复核者按 [逐角色身份验收](references/quality-gates.md#逐角色身份验收) 同看整图与脸部局部，逐人报告五官、脸型、年龄和发型的具体观察；衣装、发髻或角色可分不能代替脸部一致。
- 资料准备和独立检查可并行；有依赖的空间、线稿、上色和修订必须串行。不重复套用项目的对抗式代码审查技能。
- 没有独立复核工具时注明“独立复核未执行”，可完成不依赖它的工作；不得以角色扮演伪造独立通过，交付仍保留待核项。

## 收尾与范围

- 状态使用“当前使用／候选／待修正／停用”，另记用户是否确认以及是否接入；模型复核通过不能升级为用户已确认。
- 角色图生成、修改或确认后按根 `AGENTS.md` 更新身份索引，链接本图记录；仅用户确认的母版变更和可复用身份经验写入角色标准，不把新图反向变成母版。
- 定稿进入项目时复制已确认原图并核对哈希；正式单镜素材默认目标 1920×1080，分镜台本按上述整页布局交付；记录工具原生尺寸与实际显示方法，不能虚报像素尺寸或默默拉伸。当前授权不足以改变尺寸时保留原图并说明差异。
- 获得接入授权后，核对引用再注册资源和稳定代号，运行 `tools/build_image_catalog.py --check`，按影响范围做 Ren'Py lint 和切镜、对白、存读档、回退/回看实机验证。未运行就写明，不沿用旧验收。
- 交付包含修改文件、采用资产、实现结果、验证结果、未验证项和风险。保留旧资产及制作记录，不批量删除、不自动推送或对外上传。
